# M0: the voice and core prototype

**Status:** done, 2026-10-21. Deployed on the owner's Cloudflare account, and the smoke test (§4) passed on that deployment. Under VISION rule 7, a smoke test on the real deployment now marks a milestone done, in place of a week of use. One exit check, voice latency, isn't met yet; the owner accepted that for M0, and it carries into M1 (§4 and [HANDOFF-M1.md](HANDOFF-M1.md)).

M0 proves two things (VISION §25): the platform works, and voice can be one mind. It is one person agent on Cloudflare with the log, minimal records, the character, two tools (calendar read and reminders), voice with ElevenLabs, ChatGPT sign-in and Workers AI as brains, a bare thread, and the benchmark that picks the `voice` and `speech_in` defaults.

**Exit checks:**
- With no lookup, half of replies start speaking within 1 second. *Not measured yet: the benchmark hasn't been run (§2).*
- With a lookup, an honest status line comes within 1 second. *Not met yet: 2.5 s measured (§4).*
- Voice gives the same answers as text. *Met: voice and text use the same loop, context and tools, and gave the same calendar answers in the smoke test.*

## 1. Deploy it

You need a Cloudflare account on the Workers Paid plan ($5 a month), Node 22 or newer, and git. The default Workers AI models, such as Kimi K2.6, aren't available on the free plan, and VISION §19.3 needs Paid anyway. With Paid, Atlas answers on Workers AI as soon as it's deployed, before you add anything else.

```sh
git clone https://github.com/maxjb-xyz/atlas && cd atlas
npm install
npx wrangler login
npm run deploy                                # prints https://atlas.<your-subdomain>.workers.dev
openssl rand -base64 32                       # make an owner secret; keep it in your password manager
npx wrangler secret put ATLAS_OWNER_SECRET -c core/wrangler.jsonc   # paste it
```

Then open the URL and sign in with the secret. In **Settings**:

1. **Atlas:** your name, and check the time zone (it's taken from the first browser that connects).
2. **Brains:** press **Sign in with ChatGPT**, open the sign-in link, and allow Atlas to use your plan (Plus or Pro). Your browser then lands on a page at `127.0.0.1` that won't load. That's expected: copy its address and paste it into Atlas. Atlas then lists the models on your plan and points the ChatGPT spots in your brain chains at one of them. Press **Test** on each brain in both chains.
3. **Voice:** paste your ElevenLabs API key and press **Test voice**. Without a key, Atlas speaks with Workers AI's Aura voice.
4. **Calendar:** make an app-specific password at [account.apple.com](https://account.apple.com) (Sign-In and Security → App-Specific Passwords), enter your Apple ID and that password, and press **Test**. It should say how many calendars and events it found.

Redeploying (`npm run deploy`) is safe at any time. Your log, settings and sign-ins live in the agent's storage and survive it.

## 2. Run the benchmark

The benchmark speaks ten prompts into the deployed Atlas in real time, the same way the app does, and measures from the end of the speech to the first audio back. Five prompts need no lookup, and five need the calendar or reminders. It also asks the same prompts in text and lines up the tools and answers.

```sh
ATLAS_OWNER_SECRET=... ELEVENLABS_API_KEY=... npm run bench -- --url https://atlas.<you>.workers.dev
# try every voice brain and speech-in option in bench/candidates.json:
ATLAS_OWNER_SECRET=... npm run bench -- --url https://atlas.<you>.workers.dev --sweep
```

- The ElevenLabs key is only used once, to record the prompts into `bench/audio/`.
- Results go to `bench/results/<time>.md` and `.json`.
- The sweep changes the voice settings while it runs and puts them back at the end.
- Bench turns land in your real thread. Any reminders they create are undone at the end. A proper bench mode is §23.7, later.

**Picking defaults:** choose the fastest `voice` brain and `speech_in` option that passes all three exit checks with answers you're happy with. Set them in Settings → Brains and Settings → Voice. Then change the defaults in `core/src/store/settings.ts` and VISION §18 in one commit, with the results file attached.

Measured latency includes your network to Cloudflare twice and the end-of-turn wait, so run it from where you'd really talk to Atlas.

## 4. The smoke test, and what it found

M0 was signed off with a smoke test instead of a week of use (VISION rule 7, changed 2026-10-21). Run it after every deploy that touches the core. Each line should just work:

**Setup**
1. Deploy, set `ATLAS_OWNER_SECRET`, open the URL and sign in.
2. Settings: the time zone is right.

**Brains**
3. Sign in with ChatGPT (link, allow, paste the address). Settings shows you signed in, with your plan's models.
4. Test each brain in both chains.
5. "hey" by text. ChatGPT answers, with no fallback note.

**Calendar**
6. Connect iCloud with an app-specific password. Test reports calendars and events.
7. "What's on tomorrow?" by text matches the calendar, including a repeating event and an all-day event.

**Reminders**
8. "Remind me to stretch in 2 minutes." A receipt shows, and the reminder arrives on time.
9. Undo another reminder from its receipt. The thread says so, and it never fires.

**Voice**
10. Test voice in Settings.
11. Talk: "how's it going?". Speech starts promptly and plays smoothly, with no gaps or skipped sentences.
12. Talk: "what's on tomorrow?". Atlas says it's checking, then gives the same answer as step 7. The tag under the reply shows the status and answer times and `calendar_read`.
13. Interrupt mid-sentence. It stops, and the reply is marked interrupted.
14. Steps 11 and 12 on a phone.

**Failure paths**
15. Refresh mid-answer. The saved answer appears once it's done.
16. Sign out of ChatGPT. Workers AI answers, with a note saying why.
17. Sign back in; an hour or more later ChatGPT still answers (token refresh).

**What it found, all fixed before sign-off:**

| Found on the real deployment | Cause | Fix |
|---|---|---|
| The workers.dev address failed with a TLS error | Cloudflare hadn't issued the certificate for a new subdomain yet | Waited; not a code issue |
| Workers AI refused Kimi K2.6 | The default Workers AI models need the Workers Paid plan | Deploy guide says so |
| Every ChatGPT request got a 403 "Unable to load site" page | chatgpt.com's bot protection blocks Cloudflare Workers | OpenAI's official plan usage over `api.openai.com` (§6) |
| iCloud: "Illegal invocation" | The CalDAV client called `fetch` as a method, which Workers rejects | Called as a plain function, with a test that fails the old way |
| iCloud refused a correct-looking login | Unclear; Apple gives a plain 401 either way. A fresh app-specific password worked | Errors now say which server refused, and what Atlas holds |
| The status line came only with the answer | The secrets scrubber held back as many characters as the longest secret (a 1,000+ character token), so nothing was spoken until the end | It holds back only a possible start of a secret |
| Voice was choppy | Streamed MP3 pieces were decoded one by one | Raw 24 kHz PCM |
| A sentence was skipped | ElevenLabs refused requests over its concurrency limit, and the provider dropped them silently | Atlas's own ElevenLabs provider: two at a time, retries, a note when a sentence fails |
| The brain's "I'm checking…" waited for the answer | A sentence only counts as finished when the space after it arrives, and that space came with the next step | The loop closes Atlas's words before tools run |
| A working app password stopped working later | Unknown. Atlas retried after refusals, and signs in from Cloudflare's shared addresses | Atlas stops asking after a refusal and signs in far less; the cause is still open (HANDOFF-M1.md) |

**Latency at sign-off** (ChatGPT `gpt-5.6-terra` as the voice brain, ElevenLabs out, Flux in), a calendar question by voice, counted from when Atlas had the owner's words: status line at 2.5 s, answer at 6.6 s. The benchmark sweep hasn't been run yet. The levers are in HANDOFF-M1.md.

## 6. Decisions made while building

- **The plain Agents SDK, with Atlas's own loop.** VISION §19.1 names Project Think. Think owns its own message store and agent loop, which would give Atlas a second log and a second loop. M0 uses the Agents SDK's `Agent` and voice mixin with one small loop of its own. The voice mixin's own message history is switched off, so the log stays the only record. Think's compaction and sub-agents are worth another look in M1.
- **Small brain adapters instead of the AI SDK.** Each provider is about 150 lines behind one interface (`core/src/brains/types.ts`). ChatGPT's plan route has its own rules anyway (tools in a namespace, no output-length setting), and this keeps the loop independent of a fast-moving library.
- **ChatGPT through OpenAI's official plan usage, not Codex's backend.** The first build called `chatgpt.com/backend-api/codex` the way the Codex CLI does. chatgpt.com's bot protection blocks requests from Cloudflare Workers (and from other cloud servers), so every request came back as a 403 "Unable to load site" page. OpenAI's [Sign in with ChatGPT](https://developers.openai.com/siwc/token-sharing-open-source), launched at DevDay on September 29, 2026, lets open-source tools use a Plus or Pro plan through the public API at `api.openai.com`, which takes server traffic. OpenAI only redirects sign-in to `127.0.0.1`, and Atlas doesn't run on your computer, so the last step is pasting the address. OpenAI's own guide for tools on remote machines works the same way. If OpenAI later allows other redirects for open-source tools, the paste step goes away.
- **Speech in is Deepgram Flux on Workers AI by default.** Cloudflare hosts it, so it needs no Deepgram account. ElevenLabs Scribe is the other option, and the benchmark compares them.
- **Speech goes to the app as raw 24 kHz PCM, not MP3.** Speech streams to the app in pieces, and each piece is played as it arrives. MP3 can't be decoded from arbitrary pieces, so it played choppily; raw samples play from any piece. Pieces are kept to whole samples and gathered to about 100 ms after the first.
- **The secrets scrubber holds back only what could be the start of a secret.** Holding back a fixed length meant holding back the longest secret, and a ChatGPT sign-in token is over a thousand characters, so whole replies, status lines included, waited for the turn to end.
- **Speech out falls back to Workers AI Aura 2** when there's no ElevenLabs key, so voice works on a fresh deploy.
- **Status lines come from the tool.** Each tool can name what it's doing ("Checking your calendar."). When the brain starts a lookup without saying anything, voice says that line. When the brain says something itself first ("I'm checking next week's calendar."), that is the status line, and the loop closes it before the tool runs so it's spoken at once. The model's own words are never changed (rule 1). Each spoken reply records when the status line and the answer were ready, and which tools ran.
- **Atlas speaks through ElevenLabs with its own small provider**, not the voice package's: at most two requests at once, retries on refusal, and a note in the thread for any sentence that couldn't be spoken.
- **iCloud is asked as little as possible.** The calendar list is kept between wakes (found afresh every 6 hours and on Test), two calendars are read at a time, and the same range asked twice within 15 s reuses the first read. After a refusal, Atlas stops asking until the owner reconnects or presses Test.
- **A reminder is delivered even when no brain answers.** Atlas phrases it when it can. When every brain fails, the owner still gets "Reminder: …", so the promise is kept.
- **Flux waits at most 2.5 s after you stop** before ending your turn, a lesson from old Atlas's voice audit. Flux's eager end-of-turn signal, which would let Atlas start sooner, is the next lever if the benchmark misses.
- **Sign-in is one owner secret** traded for a signed cookie. Passkeys come with setup in M1.
- **Secrets live in the agent's storage** (encrypted at rest by Cloudflare) until the vault in M3. The app and the model never see them.

## 7. Left for M1 and later

See [HANDOFF-M1.md](HANDOFF-M1.md) for the open issues (voice latency, iCloud reliability) and the M1 plan. Beyond those:


- **Reminders only reach the app.** There are no push notifications yet. A reminder that fires while the app is closed waits in the thread. Notifications are M2.
- **No compaction or recall.** Each run sees the last 40 messages. Records exist, but there are no tools to write or search them yet.
- **No money figures.** Tokens are recorded per message; cost per day and spending caps come with the Brains page in M1.
- **One person.** Members, faces and the home agent are M5.

```sh
npm install

npm run format
npm run dev        # builds the app, then runs wrangler dev on :8787 (needs `wrangler login`, since Workers AI is remote)
npm run dev -w app # the app alone on :5173, proxying to wrangler dev
```
